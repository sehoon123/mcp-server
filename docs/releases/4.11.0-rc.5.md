# v4.11.0-rc.5 — Isolated Release-Credential Readiness

## Compatibility

This release candidate updates the independently maintained **Independent MCP Bridge** distribution for Burp Suite
Community and Professional on Java 21. It retains the v4 Streamable HTTP transport, embedded stdio proxy, all three
negotiated MCP protocol revisions, the exact 21-tool Community and 28-tool Professional names, four Community and five
Professional prompts, and all existing resource URIs and templates. No tool, prompt, resource, template, stable
reference, cursor, approval family, or structured result contract is removed or renamed compared with
`v4.11.0-rc.4`.

Runtime behavior and dependency inputs are unchanged from RC4. RC5 changes release-evidence acquisition and identity
binding only. The Community catalog fingerprint remains
`15b9b63ea145194e982fdc4f073931cdbf7afdb340e4b7ad5011222b3c04cdbb`; the Professional fingerprint remains
`eb0415096841f806d4f93954126dcf46906b42aa75f130bb4075661690d04486`.

## Security and approval changes

- Replaces the unsupported built-in Actions-token Dependabot query with a dedicated `release-dependabot-read`
  environment secret. Missing, expired, unauthorized, rate-limited, or malformed credential responses fail closed; there
  is no fallback to `${{ github.token }}` or an operator's general-purpose OAuth token.
- Fetches Dependabot alerts in a separate no-checkout, no-project-code job with no repository permissions. The secret is
  present only in the fetch step, and only the minimized policy fields needed by the reviewed alert validator are passed
  to the source-processing vulnerability job through a one-day Actions artifact.
- Adds a main-only pre-tag credential preflight tied to one exact 40-character protected-main SHA. The authoritative
  tagged workflow queries again because alert state is point-in-time; preflight success never substitutes for release
  evidence.
- Binds `VULNERABILITY_EVIDENCE.json` directly to the exact release tag in addition to repository, source commit, proxy
  commit, coordinate-set identity, and checksummed query outputs. Draft staging, smoke, protected publication, and the
  anonymous public-byte check all reject a mismatched tag.
- Adds static workflow contract tests that prohibit candidate-code execution in the secret-bearing job, token fallback,
  secret-backed pull-request execution, and reintroduction of the built-in token path.
- Preserves RC4 project-binding privacy, structured error classification, Scanner publication ordering, cancellation
  provenance, cleanup-capacity accounting, exact catalogs, and granular approval behavior.

## Known limitations

The dedicated credential and `release-dependabot-read` environment are external repository controls. RC5 must not be
tagged until a least-privilege GitHub App or fine-grained token restricted to Dependabot-alert read access is provisioned,
the environment policy is independently reviewed, and the preflight succeeds at the exact protected-main candidate SHA.
The immutable RC4 tag and withheld draft must not be moved or reused.

A complete workflow-produced draft, OIDC provenance and attestations, and exact-byte Community and Professional Burp
smoke are still required before publication. `dataApprovalAndProjectTransition` remains `BLOCKED` because Montoya 2026.7
has no supported same-process project replacement API or lifecycle event. `scopeScannerUncertainOutcomes` remains
`BLOCKED` because no safe deterministic production reconciliation trigger or attempt ledger exists. Neither scenario may
be weakened, fabricated, or satisfied with duplicate mutation, caller disconnect, guessed UI actions, test hooks, or
prior-candidate evidence. Publication remains `WITHHOLD` until every required gate is objectively satisfied.
