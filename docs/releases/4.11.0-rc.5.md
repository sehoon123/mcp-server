# v4.11.0-rc.5 — Reader and Release Gate Hardening

## Compatibility

This release candidate updates the independently maintained **Independent MCP Bridge** distribution for Burp Suite
Community and Professional on Java 21. It retains the v4 Streamable HTTP transport, embedded stdio proxy, all three
negotiated MCP protocol revisions, the exact 21-tool Community and 28-tool Professional names, four Community and five
Professional prompts, and all existing resource URIs and templates. No tool, prompt, resource, template, stable
reference, cursor, approval family, or structured result contract is removed or renamed compared with
`v4.11.0-rc.4`.

RC5 changes bounded reader error classification, internal metadata-index coordination, release policy, and evidence
binding without changing dependency inputs or the public MCP surface. The Community catalog fingerprint remains
`15b9b63ea145194e982fdc4f073931cdbf7afdb340e4b7ad5011222b3c04cdbb`; the Professional fingerprint remains
`eb0415096841f806d4f93954126dcf46906b42aa75f130bb4075661690d04486`.

## Security and approval changes

- Classifies only the shared reader's explicit out-of-range offset exception as `invalid_argument`. An offset equal to
  the total byte length remains a valid empty terminal page, an offset beyond it returns the exact correction, and the
  final project check can still supersede the correction. Montoya and generic `IllegalArgumentException` failures remain
  sanitized Burp errors.
- Moves slow HTTP metadata source acquisition, bounded processing, and search-hint validation outside the state mutex.
  Refresh and hint builders remain independently serialized, candidates publish atomically only after project,
  generation, mutation, and cancellation checks, generation races retry at most once, and `close()` prevents late
  publication while draining active builders and project/Scope mutation blocks.
- Uses exact-coordinate OSV and normalized dev-inclusive npm audit evidence without an external alert service,
  credential broker, pre-tag credential preflight, or alert snapshot release asset.
- Removes GitHub environment bindings and required-reviewer approval steps from draft creation, exact-byte smoke, and
  no-rebuild publication. The maintainer-dispatched workflows remain bound to an immutable signed tag and exact source
  SHA.
- Reduces the required exact-byte Burp smoke contract from 13 to 11 scenarios. Project-transition and
  uncertain-execution reconciliation scenarios are outside release scope; they are removed rather than represented as
  passing evidence.
- Binds `VULNERABILITY_EVIDENCE.json` directly to the exact release tag in addition to repository, source commit, proxy
  commit, coordinate-set identity, and checksummed query outputs. Draft staging, smoke, publication, and the anonymous
  public-byte check reject a mismatched tag.
- Preserves two-build reproducibility, CycloneDX SBOM validation, exact asset allowlists, checksums, OIDC provenance,
  attestations, exact Community/Professional catalogs, and exact-downloaded-byte smoke evidence.
- Preserves RC4 project-binding privacy, structured error classification, Scanner publication ordering, cancellation
  provenance, cleanup-capacity accounting, and granular runtime approval behavior.

## Known limitations

The retired smoke scenarios are not evidence that same-process project replacement or deterministic uncertain-operation
reconciliation is supported. Existing runtime project binding, cancellation, fail-closed result handling, and
non-automatic-retry guidance remain in place and are still covered by source tests. Metadata-index concurrency tests
establish extension-side ordering and lock responsiveness, not a Burp or Montoya wall-clock improvement; a synchronous
Montoya call may still delay shutdown, but no indexed candidate or coordinated mutation remains active after close.

A complete workflow-produced draft, OIDC provenance and attestations, and exact-byte Community and Professional Burp
smoke are required before publication. Publication remains `WITHHOLD` whenever any of the 11 required smoke scenarios or
any retained identity, OSV/npm, reproducibility, SBOM, checksum, provenance, or immutable-release gate does not pass.
