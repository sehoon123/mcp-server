# v4.12.0-rc.1 — Native Utilities, Execution Workflows, and Local Activity Visibility

This is an **unpublished release candidate** of the unofficial **Independent MCP Bridge**, maintained by
[sehoon123](https://github.com/sehoon123/mcp-server), not published or supported by PortSwigger.
[Support](https://github.com/sehoon123/mcp-server/issues) belongs to this independent repository.

## Compatibility

- Requires Java 21; builds against Montoya `2026.7` for Burp Community and Professional. Exact-candidate testing in both
  editions is still required. The MCP SDK remains `0.14.0`, with negotiated revisions `2025-03-26`, `2025-06-18`, and
  `2025-11-25` over Streamable HTTP and the unchanged embedded stdio proxy.
- Expands the catalog from 21 Community / 28 Professional to 24 Community / 37 Professional tools while retaining 4/5
  prompts, fixed resources, and canonical URI templates. Community adds native ranking, annotation, and opt-in local
  commands. Professional additionally adds four Request Execution Engine lifecycle tools and two Repeater custom-action
  Bambda tools. This candidate also includes the existing v4.12 related-correlation, Scanner-delta, diagnostics, JSON
  comparison/preset, and request-only Comparer/Decoder schema changes; it is not schema-identical to v4.11 RC7. Reconnect
  clients and rediscover capabilities after upgrading.
- Includes the five-client Setup Center, bounded Connection Doctor, native workflow-preset manager, and subsequent
  preview, cleanup, confirmation, and reliability fixes already present in the development tree.
- Promotes the local source identity from `4.12.0-dev.1` to `4.12.0-rc.1`, with BApp `SerialVersion` 13. Gradle rejects
  BApp version mismatches before tests and packaging and verifies the completed JAR's version. The SBOM shares the
  Gradle version. The proxy retains its own independently pinned version and checksum.

## Security and approval changes

- Combines reburp's JSON inspection/normalization and HTTP-diff ideas with the existing stable-reference comparison
  service: `request_json` and `response_json` compare stored bodies and report bounded RFC 6901 paths against the first
  reference, without scalar values or raw excerpts. No request sending, mutation, or native variation analysis occurs.
  Existing source approval, project verification, and cancellation remain authoritative. JSON-mode `allEqual` uses
  structural equality; other comparison modes retain byte equality.
- Adopts reburp's useful Comparer/Decoder handoff idea without adding another MCP tool: `route_raw_http_request` and
  `route_http_message_from_id` now accept `comparer` and `decoder`. The existing 2 MiB request bound, routing approval,
  project checks, emergency read-only interlock, and uncertain-execution contract remain in force. Only request bytes are
  handed to Burp's native UI; responses are not included, no decoded/comparison result is returned, and no network traffic
  is generated. The idea is based on reburp commit `767329b487c647568895e6d3fba9198674d0ba14`; the bridge reuses its own
  authenticated, project-bound routing implementation rather than reburp's REST surface.
- Adds `rank_http_messages` for native anomaly ordinals over exactly 1–32 distinct stable references. Source approval,
  2 MiB per-message request/response limits, a 16 MiB exact-set limit, cancellation checks, and final project fencing
  apply. Ordinals are relative to the selected set and are not severity or vulnerability evidence; the synchronous
  native ranking call has no interruptible deadline.
- Adds `annotate_http_messages` for notes/highlight updates on 1–16 re-resolved records. The exact references and new note
  are locally reviewable; stale annotations fail before writing. Notes and color use separate Montoya setters, so a
  partial failure is `execution_uncertain` and must be reconciled rather than retried.
- Adds Professional-only `start_http_request_execution`, `queue_http_request_execution`,
  `get_http_request_execution`, and `control_http_request_execution`. Batches support bounded stored or raw requests,
  preserve source/derived/outbound/batch approvals, cap each retained run at 64 requests and 16 MiB cumulatively, retain
  metadata instead of raw results, and keep at most four active/completed/cleanup-pending handles. Project cleanup and
  unload attempt cancellation; unconfirmed cleanup continues consuming capacity.
- Adds disabled-by-default `execute_local_command` plus Professional `import_bambda` and `generate_bambda_chain`.
  Enabling the local code-execution switch requires confirmation and is not implied by YOLO mode; each invocation still
  receives sensitive-action approval unless YOLO skips only that prompt. At most 32 distinct MCP-imported Bambda IDs
  are retained per extension lifetime, while same-ID replacements reuse their slot. Shell output is fully materialized by native
  ShellUtils before the MCP preview cap. Imported or auto-running Bambdas and already-started processes can act outside
  later project, outbound-approval, toggle, and Emergency read-only checks.
- Reuses HTTP-comparison presets end to end: saved enum values, execution adapters, generated native picker choices, and
  privacy-bounded input previews. No new tool, preset store, dependency, or route is introduced. The current comparison,
  save/list/execute preset schemas change intentionally, with exact catalog fingerprints and wire tests updated.
- Adds **Recent redacted activity** under **Diagnostics and Safety**: sortable timestamps, tool/event names, outcomes,
  numeric durations, access classifications, and one-way session correlations; literal case-insensitive filtering by
  tool, outcome, or correlation; and a read-only selected-record detail view.
- Audit table rows and filter controls resize when the active UI font changes. The routing-approval checkbox uses the
  shorter label **Require approval for routing and derived requests** to fit enlarged text; its policy and confirmation
  behavior are unchanged. Synthetic light/dark layout checks retain the same clipping assertions.
- Reuses the sanitized audit snapshot, configured retention (maximum 1,000 records), existing diagnostics timer,
  clipboard export, and confirmed clear action. Selection and the selected detail's text selection/reading position
  survive refreshes; failed reads clear stale content and remain visibly unavailable even when the filter changes.
  **Clear filter** restores only the view, never deletes records. Cleanup prevents further refresh reads. No raw API or target request/response is captured, and no
  new persistence store, MCP tool, endpoint, subscription, or dependency is introduced.
- Native ranking, annotation, Request Execution, Bambda, and ShellUtils integration ideas were evaluated from reburp
  commit `767329b487c647568895e6d3fba9198674d0ba14` (`RankingRoutes.kt`, `ProxyRoutes.kt`,
  `RequestEngineRoutes.kt`, `BambdaRoutes.kt`, and `ShellRoutes.kt`). This bridge implements independent bounded MCP
  contracts rather than copying the unauthenticated REST handle/storage model.
- The activity-view idea and explicit compatibility guidance are inspired by
  [reburp's activity log](https://github.com/forefy/reburp/blob/767329b487c647568895e6d3fba9198674d0ba14/src/main/kotlin/com/reburp/ActivityLogTab.kt).
  This implementation uses the bridge's existing metadata-only audit boundary rather than reburp's raw traffic storage
  or unauthenticated REST surface. The separately requested native execution additions use authenticated MCP tools,
  explicit bounds, disabled-by-default code execution, local approval, and documented out-of-band residual authority.
- Updates only three transitive CI Node packages to remediate current feed findings: `fast-uri` 3.1.7, `hono` 4.13.7,
  and `qs` 6.16.0. Direct conformance/Ajv pins, Gradle runtime dependencies, and the embedded proxy remain unchanged.
  The local post-update npm audit returned zero findings; no vulnerability-policy exception was added.
- Retains independent approval families, loopback/bearer/Host/Origin checks, emergency read-only precedence, project
  boundaries, and conservative uncertain-execution handling for MCP calls. Existing native-confirmation and queued
  Organizer project-fencing fixes remain in place. The new code-execution switch intentionally expands an authenticated
  client's authority only after a separate local opt-in; imported/started native work cannot be retroactively confined.

## Known limitations

This source version is not a release publication or proof of release readiness. The v4.11 release-line bridge still
blocks drafting later releases until the exact predecessor identity is reviewed and pinned. SerialVersion 13 must be
reconciled against all same-UUID predecessor releases, including non-ancestor stable tags, before signing a candidate;
never change an already signed tag or published asset.

Fresh immutable-source OSV/npm evidence, independent reproducible builds, SBOM/legal/provenance validation, conformance,
and exact-byte Community/Professional and supported-client smoke testing remain publication requirements. The historical
vulnerability report is explicitly not evidence for RC1. Local tests cannot prove Burp theme, screen-reader, real-client,
large-history, or unload behavior; no new live Burp performance claim is made.

JSON comparison requires complete UTF-8 bodies within 64 KiB each, depth 32 and a 10,000-node-visit call budget, with a
conservative structural-token guard before parsing. Duplicate keys, unpaired Unicode escapes, invalid input, and exceeded input/work limits return
unknown JSON equality. Object order/whitespace are ignored; numeric literals remain lexical and arrays positional.
Only 32 differences with pointers of at most 512 characters are returned; omitted paths set `differencesTruncated`.
Paths contain member names and are still project data. JSON-mode presets cannot be decoded by older builds lacking the
new enum values; remove or convert them before downgrading. No compressed-body decoding is added.

Request Execution Engine and Bambda behavior is Professional-only and still needs exact-candidate live validation.
Native result callbacks are retained only as bounded label/status/status-code/length metadata and return `DROP` for raw
request/response retention. Engine cancellation is best effort; a handle or hidden cleanup reservation remains bounded,
but cancellation completion is not claimed until Burp reports the run finished. ShellUtils exposes no streaming output
or child-process handle, so the MCP response cap does not cap native output allocation and Emergency read-only cannot
terminate an already-started process. Generated chain Bambdas validate fixed targets, literal escaping, extraction
patterns, and header injection bounds, but only a live Burp import/run smoke can prove candidate Bambda compilation and
runtime behavior.

The activity view contains only retained completed audit records and local events, not live in-flight request progress
or full traffic history. Disabling audit logging preserves existing records but does not record subsequent calls.
Filtering affects only the view: the existing copy action still exports up to 100 recent records under its 64 KiB cap,
and confirmed clearing deletes the entire retained audit, not just visible rows.
