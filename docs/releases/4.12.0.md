# v4.12.0 — Native Utilities, Execution Workflows, and Local Client UX

Unofficial **Independent MCP Bridge**, maintained by [sehoon123](https://github.com/sehoon123/mcp-server), not published
or supported by PortSwigger. [Support](https://github.com/sehoon123/mcp-server/issues) belongs to this independent
repository.

This stable release promotes the v4.12.0 candidate line (RC1 → RC5). No earlier candidate published bytes, and no v4.11
or v4.12 tag/asset moves or is re-bound here.

## Compatibility

- Version `4.12.0`, BApp SerialVersion 19, successor of RC5's 18 for the same BApp UUID.
- Java 21, Kotlin `2.4.20`, Montoya `2026.7`, MCP SDK `0.14.0`, Ktor `3.4.3`, embedded proxy `2.2.1`, and negotiated
  protocol revisions `2025-03-26`, `2025-06-18`, `2025-11-25` are unchanged from RC5.
- The 24 Community / 38 Professional tool catalog, prompts, resource templates, 8 KiB default previews, explicit
  256 KiB cap, and structured/text compatibility mirror are unchanged, as are the 21/28 release-line catalogs.
- Installation keeps the v4.8 UUID/name/client-key migration rules in `MIGRATION_V4_8.md`; installing beside an older
  MCP Server build is not supported. Whole-number HTTP resource part segments use the prompt vocabulary (`response_body`,
  `response_mime`); unadvertised aliases return `invalid_argument` before approval or history lookup.

## Security and approval changes

- Every v4.12 approval, project-fence, emergency read-only, and mutation-uncertainty rule carries over unchanged. Native
  reads and active calls stay behind the existing per-target authorization, cumulative count/byte caps, and YOLO
  restrictions; opt-in execution and the local-command toggle remain explicitly approved surfaces.
- HTTP, WebSocket, and Scanner detail services observe Job cancellation at entry and around phase boundaries, including
  approval, source lookup, content preparation, and the final project observation, and stop before further work or
  ordinary result conversion once cancellation is observed. Native `CancellationException` remains propagated.
- Input-decode failures stay bounded: shared decoding returns schema-owned recovery hints, keeps unknown keys and parser
  messages private, and only decoding failures claim the handler did not start. Audit records retain the original
  decoder exception type.
- Scanner starts reject canonical numeric-reference duplicates, multiple-target approval includes every full prepared
  request and fails before native start if the 2,097,152-character review cap is exceeded, and shared raw HTTP/2
  validation rejects conflicting pseudo-header aliases. Existing target and insertion-point caps remain.
- Project configuration imports recheck the project after mutation-lock admission; pre-invocation failures remain
  `not_started` and possible post-invocation changes remain `uncertain` without automatic retry.
- The v4.12.0 OSV preflight found test-only `tools.jackson.core` 3.1.5 advisories; the test BOM moves to `3.1.7` and no
  runtime, proxy, plugin, or shipped dependency changes, so the extension JAR bytes are unaffected.
- Dependency remediation in this line is defensive only (build/test Kotlin `2.4.20`, Kotlin stdlib, test-only Apache
  HttpClient5 `5.6.4` / HttpCore5 `5.4.3`) and adds no request, scan, execution, observer, or logging surface.

## Known limitations

Cancellation remains cooperative: native calls and synchronous slicing are not forcibly interrupted, and no atomic
cancel-versus-return or native heap/deadline guarantee is claimed. Same-process project replacement and deterministic
uncertain-operation reconciliation remain outside the release contract rather than being represented as passing evidence.

Exact-byte Community and Professional Burp verification for these bytes is recorded only by the attested
`release-smoke` run that publication revalidates; this fragment asserts no native result of its own. Vulnerability
evidence is the workflow-generated OSV/npm record bound to the tagged commit and pinned proxy, not this document.

Unsupported Site Map and Organizer listener gaps remain documented, the Bambda selector grammar remains the bounded
shared regex subset, and no Burp wall-clock performance improvement is claimed without a fresh dual-edition measurement.
