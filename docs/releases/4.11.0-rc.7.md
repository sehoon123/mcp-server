# v4.11.0-rc.7 — Credential Cleanup and Evidence-Contract Correction

## Compatibility

This release candidate updates the independently maintained **Independent MCP Bridge** distribution for Burp Suite
Community and Professional on Java 21. It retains the v4 Streamable HTTP transport, embedded stdio proxy, all three
negotiated MCP protocol revisions, the exact 21-tool Community and 28-tool Professional names, four Community and five
Professional prompts, and all existing resource URIs, templates, stable references, cursors, approval families, and
structured result contracts from `v4.11.0-rc.5`.

RC7 is a minimal successor to the unpublished RC6 candidate. It preserves RC6's installation-scoped bearer migration
and lifecycle behavior while correcting two fail-closed release blockers: post-commit legacy cleanup cancellation and an
over-broad private-field evidence matcher. It does not require a client configuration change when the RC6 migration has
already committed, and it does not change the listener rule that explicit rotation takes effect after listener restart.

## Security and approval changes

- Keeps Montoya `Preferences` authoritative for the installation-scoped loopback bearer credential. Project-backed
  `extensionData` remains a migration source only and is never authoritative after the preference exists.
- Treats deletion of the obsolete project-scoped credential as unconditionally best-effort after an installation
  credential has become authoritative. A cleanup or cleanup-logging `CancellationException` can no longer make a
  committed migration, existing preference read, or explicit rotation report failure.
- Continues to propagate cancellation from preference reads and writes before a credential outcome is established.
  Corrupt, unreadable, unwritable, mismatched, or otherwise unconfirmed preference outcomes still fail closed.
- Narrows private-identifier field detection to complete quoted or unquoted field names without suffix matching while
  keeping malformed/raw evidence fail-closed. Parsed JSON and bounded escape decoding continue to reject exact normalized
  private keys, nested JSON strings, UUID-shaped identifiers, credential-bearing fields, and every supplied private
  runtime value. Categorical keys such as aggregate cursor/stable reference checks no longer trigger a substring false
  positive.
- Adds regression coverage for migration and rotation cleanup cancellation, cancellation from cleanup logging,
  categorical evidence keys, exact private-field variants, nested and malformed JSON, escaped private values, and
  credential-field rejection.
- Preserves loopback-only binding, strict Host/Origin and bearer validation, constant-time credential comparison,
  project binding, independent approval families, Emergency read-only precedence, bounded evidence parsing, and all
  RC5 supply-chain gates.

## Known limitations

Montoya `Preferences` do not expose a cross-process compare-and-set primitive. Concurrent first initialization or explicit
rotation by separate Burp processes using the same OS account is unsupported; run one active Independent MCP Bridge
installation per preference profile. A running listener intentionally keeps the credential captured at listener startup,
so explicit rotation still requires a listener restart and client update.

A failed best-effort legacy cleanup may leave an obsolete credential copy in the currently loaded or older project file.
The installation never consults that copy after an authoritative preference exists, and rotating the installation
credential makes obsolete copies unusable for that installation.

RC6 smoke outputs and manually normalized evidence are not reusable for RC7. Exact-byte Community and Professional
project-switch, restart, rotation, listener-cutover, second-restart, canonical eleven-scenario, privacy, reproducible-build,
OSV/npm, SBOM/checksum/provenance, protected-smoke, and no-rebuild publication evidence must be regenerated from the exact
signed RC7 candidate before publication.
