# v4.9.0-rc.1 — Analysis and Reusable Workflows

## Compatibility

This release candidate is an additive update to the independently maintained **Independent MCP Bridge** distribution.
It targets Burp Suite Community and Professional on Java 21 and retains the existing v4 Streamable HTTP protocol,
embedded stdio proxy, approval model, resource URIs, resource templates, and existing tool and prompt inputs.

The Community catalog contains 24 tools and 4 prompts. Professional adds seven Scanner/Collaborator tools and one
Scanner prompt for totals of 31 tools and 5 prompts. Existing resources and templates are unchanged. Clients must
reconnect and rediscover capabilities after upgrading. The technical `net.portswigger.mcp` namespace remains for source
compatibility and does not indicate an official PortSwigger distribution.

## Security and approval changes

- Adds the common read-only `analyze_http_session_security` tool. It analyzes 1–32 distinct ordered project-bound Proxy,
  Site Map, or Organizer references through existing source approvals and project checks. Results contain fixed,
  value-free authentication-header, cookie-attribute, endpoint-role, redirect, and cross-message classifications rather
  than raw messages, bodies, credentials, cookie values, or redirect targets.
- Adds project-scoped save, list, delete, and execute operations for bounded HTTP metadata-search, WebSocket
  metadata-search, and HTTP comparison presets. One versioned project `extensionData()` envelope is capped at 64 entries
  and 256 KiB. Runtime project IDs, stable references, cursors, connection IDs, traffic/results, raw messages, and content
  predicates are not persisted. Execution delegates to the existing approval, normalization, progress, cursor, and
  project-bound services.
- Adds `plan_repeater_tests_without_sending`, a planning-only prompt over one canonical HTTP reference. Prompt retrieval
  reads no Burp traffic. Its instructions prohibit request sending/replay, Repeater routing or tab creation, Scanner,
  editor writes, and every mutation tool, and require a later explicit user action in Burp to execute a plan.
- Preserves the v4.8 trust baseline: authenticated clients remain potentially hostile, read results are discarded after a
  project transition, potentially started mutations retain `EXECUTION_UNCERTAIN`, and caller cancellation is propagated
  after owned cleanup.

## Known limitations

This is a draft release candidate, not a stable release. The exact candidate JAR still requires recorded Burp Community
and Professional smoke testing for mixed-source session analysis and project save/reopen preset behavior. No edition-level
or persistence claim may be inferred from unit, integration, or mock tests alone.

The planning-only Repeater prompt remains release-gated until Claude Desktop, Claude Code, VS Code/Copilot, Cursor,
Codex, and MCP Inspector demonstrate that normal and adversarial focus text causes no automatic routing, Repeater-tab
creation, sending, Scanner execution, editor write, or other mutation. Prompt wording cannot technically constrain an
independent client or model.

Stable v4.9 remains sequenced after the independent v4.8 trust-baseline publication gates. Existing v4.8 tags and draft
assets are not moved, replaced, or deleted by this candidate. Publication additionally requires the protected exact-byte
smoke, independent reviewer, immutable-release token, observation-window, and no-unresolved-blocker gates documented in
`docs/NEXT_RELEASE_ROADMAP.md` and `docs/RELEASING.md`.

The bridge cannot make an externally killed stdio proxy perform graceful session cleanup; bounded idle, liveness, and
capacity-pressure eviction remain the fallback. A mutation reported as `EXECUTION_UNCERTAIN` must be reconciled in Burp
before retrying. This distribution is not reviewed, endorsed, or supported by PortSwigger and does not claim BApp Store
approval.
