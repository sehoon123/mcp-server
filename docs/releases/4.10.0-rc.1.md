# v4.10.0-rc.1 — Scale, Observability, and Operator YOLO Mode

## Compatibility

This release candidate is an additive update to the independently maintained **Independent MCP Bridge** distribution.
It targets Burp Suite Community and Professional on Java 21 and retains the v4 Streamable HTTP transport, embedded stdio
proxy, three negotiated MCP protocol revisions, existing resource URIs and templates, and every v4.9 tool, prompt, and
schema name. The Community catalog remains 24 tools and 4 prompts; Professional remains 31 tools and 5 prompts.

The release adds no remote listener, resource subscription, autonomous attack workflow, or catalog entry. Clients must
reconnect and rediscover capabilities after upgrading. Existing granular approval settings are preserved across the
upgrade and remain effective whenever YOLO mode is disabled. The technical `net.portswigger.mcp` namespace remains for
source compatibility and does not indicate an official PortSwigger distribution.

## Security and approval changes

- Adds a persistent, local-only **YOLO mode** control for operators who deliberately want to bypass all MCP approval
  prompts. Enabling requires an explicit warning confirmation in Burp; clients and MCP tools cannot enable it. The mode
  records the value-free audit decision `yolo_allow`, exposes only enabled/disabled state in local diagnostics, and
  preserves rather than rewrites the granular approval policy that resumes when the mode is disabled.
- Keeps bearer authentication, numeric-loopback binding, Host and Origin checks, input and target validation, operation
  bounds, project binding, cancellation, uncertain-execution handling, separately disabled tool families, and Emergency
  read-only mode authoritative while YOLO mode is enabled. Persistence read/write failure fails closed.
- Generation-stamps session admission and invalidates sessions, streams, approvals, Scanner state, metadata indexes,
  Collaborator state, and other project-retained state at a project boundary. Read results from a stale project are
  discarded; a mutation that may have executed is reported as `EXECUTION_UNCERTAIN` rather than retried.
- Replaces extension-owned whole-history WebSocket snapshot copying with bounded capture and revalidation while retaining
  cursor separation, stable-reference readability, privacy limits, cancellation, and project checks at 100,000-entry
  regression scale.
- Linearizes context-menu creation, clipboard/log publication, cancellation, and close so unload cannot publish late
  menu, clipboard, or logging events.
- Adds fixed-cardinality, local-only project/protocol diagnostics and exact-source/JAR disposable scale and lifecycle
  harnesses without changing the public `burp://diagnostics` schema or the MCP catalog.

## Known limitations

This is a draft release candidate, not a stable release. The exact `v4.10.0-rc.1` JAR still requires protected
Community and Professional smoke evidence after the immutable draft is built. Earlier `4.10.0-dev.1` Burp runs and their
JAR hashes are development evidence only and do not satisfy the exact-candidate publication gate.

Same-process live project replacement remains blocked until a safe disposable-project transition procedure is available.
Live mutation cancellation and reconciliation of `EXECUTION_UNCERTAIN`, the supported external-client matrix, and the
exact-candidate YOLO enable/warning/reload/disable UI matrix remain unrecorded. Raw HTTP/2 routing remains explicitly
unavailable unless a supported Burp runtime is independently validated. The bounded synthetic and whole-process RSS
probes are diagnostic evidence, not Burp product performance claims.

YOLO mode intentionally removes human approval pauses and therefore materially increases the consequence of a malicious
or compromised authenticated client. Operators must use it only with trusted local clients, keep Emergency read-only
mode available, and disable it to restore their preserved granular approval policy. Stable publication remains sequenced
behind the independent trust-baseline gates and requires every exact-byte smoke, immutable-release, review, and
observation-window control in `docs/RELEASING.md` and `docs/NEXT_RELEASE_ROADMAP.md`.
