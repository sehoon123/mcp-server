# v4.8.0-rc.3 — Independent Trust Baseline

## Compatibility

This release candidate introduces the separately branded **Independent MCP Bridge** distribution and does not replace
the official PortSwigger extension. Install `independent-mcp-bridge-all.jar` as a new extension; its BApp UUID, product
name, provider key, artifact name, and support links are independent. The Kotlin package namespace remains
`net.portswigger.mcp` for source compatibility only.

The candidate targets Burp Suite Community and Professional on a Java 21 runtime. It retains the v4 Streamable HTTP
wire contract, the 19-tool Community catalog, the 26-tool Professional catalog, MCP resources and prompts, and the
embedded stdio proxy for clients without native Streamable HTTP support. Existing configurations using the former
Claude provider key or JAR name require the migration steps in `docs/MIGRATION_V4_8.md`.

## Security and approval changes

- Treats every authenticated MCP client as potentially hostile and keeps data access, outbound network authority,
  routing, and mutation approval as independent boundaries.
- Binds reads, approvals, stable references, Scanner tasks, Collaborator operations, and mutations to the originating
  Burp project. A project transition discards read results; a side effect that may already have started returns
  `EXECUTION_UNCERTAIN` with conservative retry guidance.
- Distinguishes caller cancellation from API-originated cancellation. Caller-owned cancellation is propagated, while
  post-attempt API cancellation preserves an uncertain outcome; unpublished extension-owned Scanner tasks are cleaned
  up once before cancellation escapes.
- Adds bounded Scanner materialization, credential-safe logging and configuration output, exact HTTP/2 header checks,
  nullable-enum JSON Schema conformance, and regression coverage for transition and cancellation races.
- Ships locked and SHA-256-verified Gradle dependency graphs, a reproducible embedded proxy, exact legal and runtime
  license mappings, CycloneDX SBOM validation, source archives, checksums, and GitHub artifact provenance.
- Separates read-only builds from protected draft, exact-byte smoke, and publication workflows. Candidate identity is
  bound to a signed annotated tag, the public companion-proxy commit, source commit, workflow revision, exact asset
  allowlists, and immutable-release enforcement.

## Known limitations

The signed `v4.8.0-rc.1` source tag remains as immutable evidence of a draft-workflow trial, but its checkout-free write
job lacked explicit GitHub repository context and therefore created no release or release assets. The signed
`v4.8.0-rc.2` tag and draft remain unmodified evidence of the corrected one-shot build; post-draft validation then found
that GitHub's by-tag REST endpoint excludes drafts. This candidate resolves draft identity to a numeric release ID before
smoke or publication validation, without moving or replacing either earlier tag or the rc.2 draft.

This is a release candidate, not a stable release. Publication remains blocked until the exact draft bytes pass the
protected Community and Professional Burp smoke matrix and the candidate completes the required seven-day RC window
without an unresolved release-blocking P0/P1 defect. The smoke workflow requires explicit per-scenario results and does
not infer claims from an edition-level pass.

The bridge cannot make an externally killed stdio proxy perform graceful session cleanup; bounded idle, liveness, and
capacity-pressure eviction remain the fallback. A mutation reported as `EXECUTION_UNCERTAIN` must be reconciled in Burp
before retrying. This independent distribution is not reviewed, endorsed, or supported by PortSwigger, and this
candidate does not claim BApp Store approval.
