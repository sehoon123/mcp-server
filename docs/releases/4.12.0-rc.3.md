# v4.12.0-rc.3 — Smaller Agent Reads and Cursors

This is an **unpublished test candidate** of the unofficial **Independent MCP Bridge**, maintained by
[sehoon123](https://github.com/sehoon123/mcp-server), not published or supported by PortSwigger.
[Support](https://github.com/sehoon123/mcp-server/issues) belongs to this independent repository.

## Compatibility

- Java 21, Montoya `2026.7`, MCP SDK `0.14.0`, and negotiated revisions `2025-03-26`, `2025-06-18`, and `2025-11-25`
  are unchanged. Community/Professional retain 24/38 tools. No dependency, embedded proxy, endpoint, tool, resource,
  URI template, or prompt is added. Existing passive prompt text and initialize instructions are refined.
- HTTP, WebSocket, and Scanner detail reads now default to **8 KiB**, down from RC2's 32 KiB. Resources return only
  the default first slice; explicit limits up to 256 KiB and continuation require the corresponding detail tool.
  Byte continuation metadata is unchanged. Reconnect clients and rediscover schemas after upgrading. Request a sufficient explicit limit when a complete larger read is needed;
  otherwise smaller pages can increase the number of calls. Search result-count defaults are unchanged.
- JSON selection still returns only complete values. A selected value larger than the default needs an adequate
  explicit limit; `limit_exceeded` never contains partial JSON or a raw-body fallback.
- Private HTTP and Scanner page/snapshot/delta cursor payloads omit null members, following the existing WebSocket
  format. Cursors remain opaque and signed; old explicit-null payloads decode under the same issuer key. Key lifetime,
  restart invalidation, version, query, snapshot, and project binding are unchanged. Do not decode or reconstruct cursors
  in clients. Public nullable fields, output schemas, and the JSON text/`structuredContent` compatibility mirror remain.
- This successor uses `4.12.0-rc.3` and BApp SerialVersion 15. RC1/RC2 tags, signed source, release fragments, and
  uploaded bytes remain unchanged; these are new candidate bytes, not relabeled RC2 or development bytes.

## Security and approval changes

- No new execution or send/scan capability is introduced. Existing authentication, source/sensitive approvals, project
  fences, emergency read-only, cancellation, audit privacy, and uncertain-execution/no-automatic-retry rules remain.
- Passive guidance recommends reusing summaries and references, narrowing searches, selecting a JSON value, comparing
  references without pre-reading both bodies, and stopping pagination when enough evidence is available. It requires
  reporting incomplete coverage and treats captured content as untrusted data, not agent instructions. Prompt text
  guides clients; it does not technically enforce model behavior or replace authorization.
- Cursor signatures are still verified over the received payload before decoding. Null omission changes encoding size,
  not authority, validation, or cryptographic protection. Read limits remain byte budgets rather than whole-process
  memory caps. Regression measurements use synthetic fixtures and store sizes, not live traffic or credentials.

## Known limitations

The synthetic mirrored HTTP preview fixture shrinks from 66,914 to 17,758 UTF-8 bytes (73.5%); its HTTP cursor shrinks
from 555 to 386 characters (30.5%). Scanner page/snapshot/delta fixtures shrink from 483/470/670 to 391/378/578 characters.
These are byte/character measurements, not model-token or real-agent task benchmarks. The tool catalog is essentially
unchanged in size (130,667/197,455 bytes); initialize instructions grow from 742 to 1,100 bytes to discourage redundant
calls. Complete-read workloads may consume more calls unless the client supplies a sufficient explicit limit.

Actual Burp/client testing is still required, including the changed default previews, complete JSON selection, byte
continuation, and reconnect/rediscovery behavior. All [RC2 native-runtime limitations](4.12.0-rc.2.md) still apply.
Offline tests do not establish issue persistence, native ranking/keyword semantics, or execution cleanup behavior.

The v4.11 predecessor identity bridge, exact-byte Community/Professional smoke, fresh immutable-source vulnerability
evidence, independent isolated reproducibility, complete legal/source/SBOM/provenance validation, and protected publication
remain required. Ordinary CI and local matching bytes are not substitutes. The historical vulnerability report is not
RC3 evidence. A manually staged draft with a JAR, SBOM, and checksums is for maintainer testing, not a complete attested
immutable release, and must remain unpublished. The one-shot formal pipeline cannot retrofit that same draft; use a
successor candidate after satisfying its gates. Existing immutable tags and assets must never be moved or replaced.

Before creating the signed annotated RC3 test tag, fresh local OSV/npm checks against its committed source and pinned
proxy must pass; a failed or unavailable pre-tag check stops tagging and staging. The tag must point to the reviewed
signed source commit and must never be moved. Stage only the JAR and SBOM from successful CI at that exact SHA, plus
checksums computed over those bytes; do not rebuild for upload. Redownload the staged assets and verify bytes, hashes,
manifest identity, and tag/source linkage before handing the draft to the maintainer. This local preflight and ordinary
CI are not the authoritative tagged-workflow vulnerability attestation or formal publication approval.
