# v4.11.0-rc.2 — Reduced Surface and Bounded Request-Path Performance

## Compatibility

This release candidate updates the independently maintained **Independent MCP Bridge** distribution for Burp Suite
Community and Professional on Java 21. It retains the v4 Streamable HTTP transport, embedded stdio proxy, three
negotiated MCP protocol revisions, all existing resource URIs and templates, and the existing four Community and five
Professional prompts. The exact catalogs contain 21 Community tools and 28 Professional tools.

Compared with `v4.11.0-rc.1`, this candidate intentionally removes `transform_data`, `generate_random_string`,
`get_active_editor_contents`, and `set_active_editor_contents`. Local client utilities replace the generic transform and
random-string helpers. Burp's own editor UI replaces the focus-dependent editor pair, which had no stable target
identity. Clients must reconnect and rediscover capabilities after upgrading. Every retained tool name, description,
input schema, output schema, annotation, cursor, stable reference, result contract, and edition boundary remains
unchanged.

No remote listener, resource subscription, legacy SSE endpoint, WebSocket send operation, background indexer, parallel
Montoya acquisition, or additional alias/tool family is added. The technical `net.portswigger.mcp` namespace remains for
source compatibility and does not indicate an official PortSwigger distribution.

## Security and approval changes

- Removes the two active-editor operations because their target depended on the momentary Swing `JTextArea` focus rather
  than a project-bound stable identifier. This eliminates the risk of reading from or replacing text in an unintended
  Burp editor while preserving the existing stable-ID message read and action tools.
- Replaces count-only candidate catalog checks with exact identifier-set validation for tools, prompts, fixed resources,
  and resource templates in both editions. Malformed arrays, duplicates, substitutions, mixed editions, and non-null
  pagination cursors fail closed. Complete tool fingerprints additionally bind names, descriptions, schemas, and
  annotations in the Kotlin integration suite.
- Strengthens exact-smoke evidence admission: record and objective-evidence paths must be canonical, physically unique,
  cross-role disjoint regular files; schema version must be the integer `1`; malformed recognized text, nested/escaped
  private identifiers, Unicode surrogates, symlinks, hard links, traversal, and cross-batch evidence reuse are rejected.
- Uses the retained read-only `check_scope` tool for preflight and validates project, target order, URL, index, and real
  boolean scope state. No preflight probe performs network traffic or mutation.
- Reuses invocation-local Proxy/Organizer source views, performs one filtered lookup per represented source for ordered
  batches of at most 32 references, and moves complete structured-result materialization to the existing bounded
  dispatcher. Caller order, duplicate handling, approval families, cancellation, project rechecks, stable-ID identity,
  and first-failure attribution remain explicit.
- Moves bounded audit JSON encoding and persistence outside the audit lock. Each record is serialized once, the existing
  1 MiB complete-record cap remains exact, and revision checks prevent racing append, clear, retention, failure, or close
  operations from losing or resurrecting records. Audit fields remain value-free and redacted.
- Preserves bearer authentication, numeric-loopback/Host/Origin restrictions, Emergency read-only precedence, granular
  approval policies, YOLO boundaries, cancellation propagation, project-generation invalidation, and conservative
  uncertain-execution guidance.

## Known limitations

This candidate still requires the protected exact-byte Community and Professional smoke matrix before publication. A
local build, an earlier candidate's evidence, or an all-pass unit suite does not replace native HTTP, embedded stdio,
project-transition, cancellation, independent-approval, Scanner/Scope uncertain-outcome, scale, and active-unload
evidence for the exact draft JAR.

The pinned Montoya Site Map API exposes no paginated or direct positional lookup. Site Map search, metadata refresh, and
stable-ID validation can therefore acquire the complete returned list before extension-side bounded work. Replacing
that call would require preserving the list position embedded in current stable IDs and reorder/removal detection.
Metadata-index refresh also remains serialized under its mutex until live contention evidence justifies a
generation-checked single-flight design. This candidate makes no new Burp wall-clock or allocation claim for either
path.

Source-change signals remain advisory because the pinned API provides no external Site Map or Organizer item listener.
Bounded anchors and the 30-second expiry remain required. Direct synchronous Montoya list acquisition is cancellable
only before and after the API call returns. The immutable `v4.11.0-rc.1` tag, draft, notes, and assets remain unchanged.
