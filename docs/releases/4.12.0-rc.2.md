# v4.12.0-rc.2 — Bounded Evidence Reading and Human-reviewed Reporting

This is an **unpublished release candidate** of the unofficial **Independent MCP Bridge**, maintained by
[sehoon123](https://github.com/sehoon123/mcp-server), not published or supported by PortSwigger.
[Support](https://github.com/sehoon123/mcp-server/issues) belongs to this independent repository.

- Java 21, Montoya `2026.7`, MCP SDK `0.14.0`, negotiated revisions `2025-03-26`, `2025-06-18`, and `2025-11-25` remain

  remain fail-closed until reviewed.

## Security and approval changes

- Professional `create_scanner_issue` records one caller-authored finding from 1–8 canonically distinct existing HTTP
  references. Required `humanReviewed: true` is an attestation, not proof that a human validated the claim. The tool starts
  no scan and sends no request. It never invents evidence or returns an unverified issue ID.
- Source approval precedes evidence access; sensitive-action approval shows the resolved project, all caller fields,
  references, services, URLs, and exact base64 evidence. Name/detail/remediation are plain text and HTML-escaped for Burp.
  Complete request/response parts are capped at 256 KiB each and the evidence set at 1 MiB. Post-approval re-resolution
  inside the existing mutation barrier rejects stale content, URL, or service before adding the issue.
- Emergency read-only, cancellation, project boundaries, and audit privacy remain authoritative. YOLO may skip the local
  sensitive prompt, not input validation or the emergency interlock. The audit contains operation metadata, not issue text
  or traffic. Native failure after invocation or a subsequent project transition returns `execution_uncertain` with
  `do_not_retry` and suppresses project-dependent result metadata. Native add completion is not independent persistence
  verification; check Burp before a manual retry. A later transition cannot undo an accepted issue.
- `get_http_message.jsonPointer` selects a complete strict RFC 6901 value from an explicit request/response body. It
  supports escaped keys, ordered arrays, and root selection; JSON null is distinct from missing. Nonzero offset/base64
  are rejected. Input must fit 64 KiB, depth 32, and 10,000 node visits; the selected serialized UTF-8 value must fit the
  existing output limit. Invalid UTF-8/JSON, duplicate keys, or limits return no partial value or raw-body fallback.
  This branch does not fetch unrelated source metadata. The shared JSON comparison budget remains aggregate across all
  documents and comparison work.
- `compare_http_messages.responseKeywords` is runtime-only: 1–32 distinct keywords, at most 256 characters each and 4,096
  total, for response parts only. Native analysis uses complete stored responses regardless preview size, with 1 MiB
  per-response and 4 MiB aggregate limits. Results must partition exactly the supplied keywords; oversized/unexpected
  native output or native failures produce a bounded sanitized skipped result. Keywords are not persisted in presets.
- These evidence/reporting ideas were evaluated from reburp commit `20b6efb568128e2cb5fdf5b313a14b183f15c7d7` and implemented
  using this bridge's existing authentication, stable-reference, parser, approval, and audit paths. No event timeline,
  subscription, compression framework, generic transforms, or additional send/scan workflow is introduced.

## Known limitations

This candidate is not public-release readiness evidence. The v4.11 predecessor identity bridge remains closed; exact-byte
Community/Professional smoke, fresh immutable-source vulnerability evidence, independent isolated reproducibility,
SBOM/legal/provenance validation, and the protected publication workflow remain required. Any manually staged draft is
not an attested immutable release. The historical vulnerability report is not RC2 evidence.

Offline mock-based tests do not establish native issue persistence, HTML rendering, evidence attachment, or keyword
partition semantics in live Burp. Confirm actual fields/evidence and post-action state, not merely a successful status.
The synchronous native keyword analyzer has no interruptible deadline; cancellation is cooperative around native calls.
No decompression or MIME correction is added. Selected JSON values remain approved project data, not redacted metadata.

All RC1 limitations still apply: native ranking direction/identity needs live confirmation, cleanup may retain bounded
Request Execution reservations, ShellUtils materializes full output before preview truncation, and already-started
processes or imported/auto-running Bambda code remain outside later MCP project/toggle/emergency checks. RC2 does not
expand or repair those execution surfaces.
