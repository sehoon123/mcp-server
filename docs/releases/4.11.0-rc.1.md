# v4.11.0-rc.1 — Measured History Freshness and HTTP Activity Correlation

## Compatibility

This release candidate is an additive update to the independently maintained **Independent MCP Bridge** distribution.
It targets Burp Suite Community and Professional on Java 21 and retains the v4 Streamable HTTP transport, embedded stdio
proxy, three negotiated MCP protocol revisions, existing resource URIs/templates, and the existing four Community and
five Professional prompts. The Community catalog contains 25 tools and Professional contains 32 after adding exactly one
common read-only `correlate_http_activity` tool. Existing tool names, inputs, cursors, stable references, and result
schemas remain unchanged.

Clients must reconnect and rediscover capabilities after upgrading. No remote listener, resource subscription, legacy
SSE endpoint, WebSocket send operation, background indexer, parallel Montoya acquisition, or additional alias/tool family
is added. The technical `net.portswigger.mcp` namespace remains for source compatibility and does not indicate an
official PortSwigger distribution.

## Security and approval changes

- Adds fixed-cardinality, value-free acquisition and processing measurements for HTTP metadata indexing/search and
  WebSocket search. They are extension-lifetime local diagnostics shown only in Burp's diagnostics panel; they do not
  change `burp://diagnostics`, persistence, audit records, logs, or any MCP result schema.
- Adds constant-time advisory source revisions from mutation-neutral Proxy/Scanner callbacks and approved Organizer
  attempts. Callbacks retain no traffic or Montoya object, return the exact continued message/annotations, and never
  block on history access. Existing bounded anchors, source lists, expiry, generation, and final project checks remain
  authoritative.
- Extracts shared bounded path/status/MIME/extension metadata helpers, canonical reference identity, and a least-data
  `PROXY_CAPTURE_TIME` resolver mode. Existing reads continue to use full metadata; the new mode reads only Proxy capture
  time beyond normal reference resolution.
- Adds `correlate_http_activity` for one to 16 globally distinct baseline references and one to 16 globally distinct
  comparison references. It resolves one ordered batch through existing per-source approval and stable-ID checks,
  returns at most 32 bounded events plus a complete deterministic metadata-count delta, and performs no traffic or
  mutation. Non-success results expose no partial timeline, group, or delta.
- Preserves bearer authentication, numeric-loopback/Host/Origin restrictions, input bounds, project-generation
  invalidation, Emergency read-only precedence, granular approval policies, cancellation propagation, stable-ID
  revalidation, audit redaction, and uncertain-outcome handling. YOLO mode can bypass approval prompts only under its
  existing local policy and does not weaken any of those controls.
- Records the canonical GitHub repository URL in generated `SOURCE_IDENTITY.json` and revalidates it before draft
  creation, aligning immutable draft provenance with the protected publication preflight.

## Known limitations

This is an immutable draft release candidate, not a stable or publicly approved release. The exact
`v4.11.0-rc.1` JAR still requires protected Community and Professional load/catalog/correlation smoke evidence, native
HTTP and embedded stdio checks, project-transition/cancellation/unload evidence, and the remaining gates in
`docs/RELEASING.md` and `docs/NEXT_RELEASE_ROADMAP.md`. Development JAR hashes and earlier v4.10 live runs do not satisfy
this candidate's exact-byte publication gate.

Only Proxy references expose capture time. Caller order and baseline/comparison membership do not establish chronology,
causality, exact cross-source identity, or vulnerability evidence. Similarity groups are invocation-local bounded
metadata associations; records are never deduplicated. Correlation results retain and return no query string, fragment,
header, body, note, or raw-message value, but existing Site Map stable-ID validation may privately inspect bounded URL,
header, and body identity samples. Bounded normalized paths and hosts remain visible under the existing approved
attack-surface metadata contract.

Source-change signals are advisory. The pinned Montoya API provides no external Site Map or Organizer item listener, so
bounded anchors and the 30-second expiry remain required. Direct Montoya history/list acquisition can still scale with
the complete source and is synchronously cancellable only before and after the call returns. No single-flight refresh or
parallel acquisition is included because its live entry gate has not passed. The immutable `v4.10.0-rc.1` tag, draft,
notes, and assets remain unchanged.
