# v4.9.0-rc.2 — Agent-facing Contract Corrections

## Compatibility

This release candidate is an additive metadata correction to the independently maintained **Independent MCP Bridge**
distribution. It targets Burp Suite Community and Professional on Java 21 and retains the v4 Streamable HTTP protocol,
embedded stdio proxy, approval model, annotations, behavior, resource URIs and templates, and all existing tool and prompt
names, input/output field names, and schema constraints. Description metadata is corrected, along with the misleading
HTTP/2 Intruder rejection message; its unconditional rejection behavior is unchanged.

The Community catalog remains 24 tools and 4 prompts. Professional remains 31 tools and 5 prompts. Clients must reconnect
and rediscover capabilities after upgrading. The technical `net.portswigger.mcp` namespace remains for source
compatibility and does not indicate an official PortSwigger distribution.

## Security and approval changes

- Corrects tool descriptions to match HTTP/1.1 line-ending normalization, unconditional HTTP/2 Intruder rejection,
  configuration credential filtering and edit enablement, Scanner legacy/cursor selection, conditional evidence indexes,
  Scanner scope checks, exclusive Collaborator timestamps, editor statuses, preset replacement/default limits, and
  cursor continuation through the `cursor` input.
- Reworks the catalog against the official MCP tools, server-concepts, and client-discovery guidance: descriptions now
  identify each focused operation and its observable side effects concisely, while detailed formats, conditional inputs,
  continuation handoffs, examples, defaults, and bounds live in JSON Schema property descriptions.
- Makes approval, project-bound access, bounded output, no-send routing, private session-analysis reads, and uncertain
  execution/do-not-retry boundaries explicit without changing their implementation.
- Adds missing input-property descriptions for raw routing, local utilities, configuration, bounded reads, request patches,
  insertion points, Collaborator filters, and workflow presets. Names and constraints are unchanged.
- Describes `analyze_http_without_sending` as supplying safety instructions rather than technically enforcing independent
  client or model behavior.

## Known limitations

This is a draft release candidate, not a stable release. The exact candidate JAR still requires recorded Burp Community
and Professional smoke testing for mixed-source session analysis and project save/reopen preset behavior. No edition-level
or persistence claim may be inferred from unit, integration, or mock tests alone.

The planning-only Repeater prompt remains release-gated until Claude Desktop, Claude Code, VS Code/Copilot, Cursor,
Codex, and MCP Inspector demonstrate that normal and adversarial focus text causes no automatic routing, Repeater-tab
creation, sending, Scanner execution, editor write, or other mutation. Prompt wording cannot technically constrain an
independent client or model.

Stable v4.9 remains sequenced after the independent v4.8 trust-baseline publication gates. Existing v4.8 and v4.9.0-rc.1
tags, notes, and draft assets are not moved, replaced, or deleted by this candidate. Publication additionally requires the
protected exact-byte smoke, independent reviewer, immutable-release token, observation-window, and no-unresolved-blocker
gates documented in `docs/NEXT_RELEASE_ROADMAP.md` and `docs/RELEASING.md`.

The bridge cannot make an externally killed stdio proxy perform graceful session cleanup; bounded idle, liveness, and
capacity-pressure eviction remain the fallback. A mutation reported as `EXECUTION_UNCERTAIN` must be reconciled in Burp
before retrying. This distribution is not reviewed, endorsed, or supported by PortSwigger and does not claim BApp Store
approval.
