# v4.12.0-rc.5 — Consistent Resource Parts and Read Cancellation

This is an **unpublished test candidate** of the unofficial **Independent MCP Bridge**, maintained by
[sehoon123](https://github.com/sehoon123/mcp-server), not published or supported by PortSwigger.
[Support](https://github.com/sehoon123/mcp-server/issues) belongs to this independent repository.

## Compatibility

- Version `4.12.0-rc.5`, BApp SerialVersion 18. RC4 and all earlier tags/assets remain unchanged.
- Java 21, Kotlin `2.4.20`, Montoya `2026.7`, MCP SDK `0.14.0`, Ktor `3.4.3`, embedded proxy `2.2.1`, and negotiated
  protocol revisions `2025-03-26`, `2025-06-18`, `2025-11-25` are unchanged. Runtime dependency versions and the proxy
  pin are unchanged; audit cleanup removes the unused direct test dependency `ktor-client-content-negotiation`.
- The 24 Community / 38 Professional tool catalog, schemas, prompts, resource templates, 8 KiB default previews,
  explicit 256 KiB cap, and structured/text compatibility mirror remain unchanged.
- HTTP resource part segments now use the same exact vocabulary as prompt references. Use `response_body` or
  `response_mime`, not case/hyphen/whitespace variants. Previously tolerated, unadvertised resource aliases now return
  `invalid_argument` before data approval or history lookup. The detail tool retains its existing part normalization;
  project/reference formats and canonical resource paths are unchanged.

## Audit cleanup

- The server enable control uses a native Swing toggle instead of custom painting, slide animation and particles;
  keyboard activation, accessibility, validation and callback-silent programmatic state updates are retained.
- Unused serialization adapters/DTOs, reflection schema generation and a text-button factory are removed. The plain
  structured registration helper delegates to the existing context-aware helper without changing MCP contracts.
- The auto-approved target list and documentation links use native Swing list/button behavior instead of custom
  rollover rendering and label interaction. Keyboard controls, accessibility, validation and mutation error reporting remain.
- Message dialogs rely on existing width-aware text wrapping, preserving original spacing and explicit newlines.
  Three unused registration overloads and constant internal Site Map result plumbing are removed; automatic Site Map
  recording remains disabled with unchanged public result fields and warnings.

## Security and approval changes

- HTTP, WebSocket, and Scanner detail services observe Job cancellation at entry and around phase boundaries, including
  approval, source lookup, content preparation and the final project observation. Once cancellation is observed, they
  stop before further work or ordinary result conversion, including when a native getter returns normally or throws
  an ordinary exception after the Job was cancelled. Explicit native `CancellationException` remains propagated.
- The existing project fences, approval/denial paths, error sanitization, pagination and selected-value bounds remain.
  Shared service fixes apply to both tool and resource callers. The shared data-approval helper and HTTP reference
  resolver have matching checkpoints, including after approval/logging and before post-resolution project checks.
  Existing resolver consumers reuse these read/preparation checks; mutation dispatch and authorization policy are unchanged.
- The exact HTTP-part helper removes duplicate resource/prompt vocabulary. Malformed URI aliases do not obtain source
  access. No new request, scan, execution, mutation, observer, persistence or logging surface is introduced.

## Tool contract hardening

- Project configuration imports recheck the project after mutation-lock admission; pre-invocation failures remain
  `not_started`, while possible post-invocation changes remain `uncertain` and must not be retried automatically.
- Shared regex validation rejects multiple optional quantifiers outside escapes/classes. HTTP/WS search and generated
  Bambda selectors share this restriction; no general linear-time guarantee is claimed.
- Scanner starts reject canonical numeric-reference duplicates. Multi-target approval includes every full prepared
  request and fails before approval/native start if the existing 2,097,152-character review cap is exceeded, including
  under YOLO. Existing target/insertion-point caps and approval gates remain.
- Scanner terminal state inference uses exact normalized aliases, not substring matches. `taskState` remains a best-effort
  observation; actual cancellation and `actionState` side-effect semantics are unchanged.
- Shared raw HTTP/2 validation rejects conflicting pseudo-header aliases and pseudo-headers in the regular-header map.
  This also protects raw inputs to Request Execution start/queue; valid standalone aliases remain accepted.
- Metadata clarifies Collaborator per-field/aggregate preview limits, emergency read-only stopping restrictions, and the
  need to inspect Bambda `importStatus`/`importErrors` even when the outer status is `ok`. Names, wire schema constraints,
  defaults, enums, bounds, annotations, retained error classifications, dependencies and proxy pins are unchanged.
- New checks use synthetic fixtures and mocked native APIs. Real Community/Professional Burp validation is **NOT RUN**;
  this fragment does not authorize tagging or publication.

## MCP discovery metadata

- Initialize advertises the existing independent product's display title and source URL, without changing its machine
  name, version, capabilities, protocol, or instructions. Fixed resources gain display titles via the existing SDK
  registration API; their names, URIs, MIME types, read handlers, approval/audit/session wrappers remain unchanged.
- Regex inputs describe the existing bounded grammar rather than claiming unspecified safety. Configuration import
  guidance reflects partial settings and warns against re-importing filtered exports; no validator/import behavior changes.
- Scope summary text no longer cites an obsolete Montoya version or implies that its limited summary enumerates rules.
  These are metadata/text changes, not new tools or a claim of installed-client rendering or real Burp validation.

## Known limitations

Cancellation remains cooperative. Native calls and synchronous slicing are not forcibly interrupted, and no atomic
cancel-versus-return or native heap/deadline guarantee is claimed. The outer MCP dispatcher already propagates
cancellation; this fixes service-layer follow-up work and result handling, not a demonstrated cancelled-wire data leak.
Tests use synthetic native accessors and actual Job cancellation, not real Burp interruption experiments.

Fresh local pre-tag OSV/npm checks must cover the exact committed server and pinned proxy against the reviewed
[206-coordinate v4.12 candidate baseline](../../security/README.md). Failed or unavailable checks block tagging. This fragment is not proof that
those checks or CI passed; retain their actual source-bound records.

The frozen formal 204-coordinate workflow contract, v4.11 predecessor/successor bridge, actual exact-byte Community and
Professional Burp smoke, isolated release-grade reproducibility, complete legal/source/provenance, and protected
publication remain separate requirements. All [RC4 limitations](4.12.0-rc.4.md) remain. A manually staged test draft is
not a complete attested immutable release and must remain unpublished; do not retrofit it into the one-shot formal
pipeline. Use only exact successful-CI bytes, redownload and verify them, and never move existing tags or replace assets.
